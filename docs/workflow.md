# dsh-长任务自主审查模式

单包提供执行协调、本地 Laya／云端 Jev 验收、会话模式、设置与实时侧栏。目标运行时为 DSH 0.2.1-rc.3。

在新建空白会话的原生模式菜单中选择“长任务模式”，与标准、PTC、极简、创造模式并列；默认模式保持不变。首次发送任务后才创建长任务，模型不能自行开启。会话开始后模式固定；已有长任务的暂停、继续、结束和新建操作收拢在会话顶部的“长任务”菜单。普通会话不显示额外模式条。在设置中选择并配置本地 Laya 或云端 Jev，再提交任务。应用或插件重载后等待用户继续；结果不确定的旧动作需先核查并确认。

主模型按 `loop_tasks` 返回的 `claude-loop-plan/v1` 模板创建 `plan.md`。Host 校验后，只接收当前项的 `taskUpdate={id,status,result,evidenceIds}`。已通过结果、证据和评分不能用摘要改写。`laya_tasks` 是同一实现的兼容别名。旧会话和计划格式可读取；安装不会补写旧评分。

执行任务在 `affectedPaths` 声明实际交付路径，并提供真实回执。纯内容分析可显式声明 `taskType: "opinion"`，不需要虚构执行回执。Host 通过任务文件系统记录 SHA-256，支持二进制、目录成员、新增/删除和目录内软链接。拒绝越过工作目录的链接、特殊文件与检查不完整结果。默认限制 512 项、深度 32、单文件 16 MiB、总量 64 MiB。

旧交付物变化会显示任务与路径，阻止新的通过提交。核查后单独提交 `revalidateTaskIds` 与 `repairAnalysis`，只复验对应项。通过事实保留，复验追加新记录。这是验收边界检测，不是阻止任意 shell 写入的系统沙箱。

默认连续三次无进展或未通过后暂停；仅改措辞不能刷新执行证据进展或重复评分。用户“继续”允许新一轮有限修复，累计评分、Token、工具和时长预算仍保留。当前任务阈值固定，设置中的阈值调整对新任务生效。所选验收模型不可用时明确阻塞，不自动切换服务或降级为主模型自评。

设置可调整工具、评分、时长、模型 Token 与可选费用预算。费用按用户填写的每百万输入/输出 Token 单价保守估算，预算和单价使用相同币种，不扣缓存折扣；启用费用预算后，用量缺失会阻塞。预算在回合或工具边界检查，不能撤销已在途调用。

持久状态使用 `plugin:long-task/state` 旁路日志记录，不进入模型上下文，也不依赖聊天摘要。通过记录和用户模式操作在返回前 flush；记录版本变化必须保留转换。这是独立插件记录，不修改已发布的 DSH 会话格式。

构建：`node scripts/build.mjs`。回归：`node --test tests/runtime.test.mjs`，使用正式 rc.3 Loader、Agent、Gateway、文件系统、压缩和 JSONL 持久化，仅外部推理脚本化。`tests/laya-live.mjs` 检查真实本地 Laya；`tests/live-e2e.mjs` 使用现有登录在临时目录调用真实主模型与 Laya。

迁移前备份 profile，四个旧 bundle 与新包不能同时推进任务；失败回退。未通过真实调用或客户端检查时，不能把构建通过当成正式验收完成。

## Claude Loop 与验收接口（0.2.0）

设置保留四个原预设：省心默认、长任务不打断、省钱模式、稳妥复核。预设只填入草稿，保存后生效；高级设置保留原循环参数，工具发现开关和每轮工具步数可直接调整。长任务总预算与每轮工具上限同时生效。侧栏保留工具调用统计。

模型验收可自主选择本地 Laya 或云端 Jev。本地页保留启动器、设备、检查点、预加载、离线缓存、超时、连接状态及实际发现的工具和参数，新增固定样例校验。

Jev 使用 [TypeSafe System One HTTP 协议](https://docs.typesafe.ai/api/system-one)：完整接口地址默认 `https://api.typesafe.ai/v1/systemone`，模型默认 `jev-latest`。可填写兼容该协议的代理地址，不能填 Chat Completions 地址。Host 发送 `model/state/questions`，根据五级 Score 的0–4归一化；必选条件仍必须通过 Choice 判断，不能用置信度冒充分数。接口只接受 HTTPS，回环代理允许 HTTP；拒绝带用户名、密码、查询参数或片段的地址，不跟随重定向。

密钥通过凭据服务保存，普通配置和任务只持有引用。保存成功显示“已配置，尚未校验”；点“校验 Jev 模型”才发送固定小样例，验证真实 HTTP 及响应结构。样例不会改变任何任务进度。生产任务选择云端后会将需求、结果及引用证据发送到所保存的接口。默认保持本地，不会主动向云端发送任务。没有配置密钥时不能启动云端任务。

新任务保存验收服务快照；修改全局服务仅影响新任务，旧任务（包括未带新字段的历史记录）保持原本地服务。Jev 首次评分后保存实际模型版本，后续直接请求该版本，服务返回不同版本时停止并保留通过记录。相同地址的密钥轮换可供旧任务继续使用；换地址需重新填写密钥，原任务保留旧地址和引用。更换地址创建的旧凭据引用会保留以便恢复旧任务。应用重启后连接校验状态需要重验，保存的配置和验收事实保留。

Jev 缺字段、非法数值、概率不完整、HTTP错误、超时或取消均不能产生通过记录。没有自动重试或其他模型兜底；用户修复配置后可显式继续。云端调用受评分次数预算控制；Token/费用估算目前统计主模型用量，不包含 Jev 服务账单。

本次使用真实 rc.3 Loader/Gateway/凭据服务/HTTP，外部 Jev 响应使用本地隔离服务脚本化。无用户 Jev 密钥，未执行真实云端评分及质量验收；不能把接口回归当成云端模型效果已通过。
